# mdtero PRD 草稿（2026-10-23 群内讨论后更新，待 Jianbin 确认）

## 1. 定位
mdtero 是 AI 编程和研究工具（Claude Code、Codex、Cursor、ChatGPT、Grok Bot 等）的文献层：把任何一篇论文变成干净、可追溯的 Markdown，存进用户的私有文献库，再通过 MCP 交给 AI 使用。
差异化来自三样东西：独有的解析能力、用用户自己的网络取全文的能力（本机客户端和全文出口），以及私有文献库。
- **存储现状（已查清）**：文献库在腾讯云服务器本地磁盘和 Postgres 上（83 篇、2 个用户）。R2 `mdtero-artifacts` 里只有用户手动存到云端的 4 篇。
- **R2 自动同步**（#81 之后约 1 天）验收：入库后 5 分钟内出现在 R2；删除和 14 天到期会同时删掉 R2 副本；文件放在每个用户各自的私有路径下。做完之前，对外只写「私有文献库」，不写「5 GiB 私有云端文献库」。
- mdtero 和 trove 是两个项目，彻底分开，互不依赖，也不共用桶。

## 2. 产品线
| 对外名称 | 作用 | 状态 |
|---|---|---|
| mdtero 网站 | 账号、文献库、设备、服务与密钥、订阅、已授权的应用 | 保留 |
| mdtero 客户端（桌面版） | 取订阅全文、一键接入 AI、文献库、阅读器、研究模式 | 主力 |
| mdtero 客户端（无界面版，`mdtero` 命令） | 在 Pi、NAS、服务器上当全文出口，用设备码登录 | 保留，改用 Go 核心 |
| MCP | 把文献库和取全文能力接进 AI 软件 | 第一优先 |
| 浏览器扩展 | — | 冻结，加迁移横幅 |

界面上不出现 Connect、relay、Pi 这些内部名，relay 对外叫「全文出口」。

### 2.1 共享 Go 核心（架构决定）
- 用一份 Go 核心替换现在 PyInstaller 打包的桥接，桌面版和无界面版共用；CLI 只做一层薄壳。
- Python 版 relay 和 CLI 归档，不再维护。
- 接口契约放在公开仓库 doi2md 的 `contracts/` 目录下（含状态码对照表），客户端、服务端和 MCP 共用。

## 3. 目标用户与核心场景
目标用户：大量读英文论文、用 AI 工具写代码、做综述的理工科研究者。
1. 在 AI 软件里说"读一下这个 DOI"，就能拿到全文，订阅论文也一样。
2. 检索自己的文献库，按段落引用放到语义检索之后（P4）。
3. AI 取来的论文先进待确认区，用户确认后才存进文献库。
4. 选几篇论文，点一个预设任务，侧边栏就生成一份带出处的 Markdown 文档。

## 4. 信息架构
三个板块：**文献库**、**阅读器**、**AI agent（研究模式）**。**检索**放在最上层，任何页面都能直接用。

## 5. 最小闭环（当前第一优先）
现在一个真实用户都没有，先跑通最小闭环，再谈投入。客户端不定上线日期，先把功能和 UI 做好。
- **验收**：新用户 10 分钟内走完：下载安装 → 整窗登录页（不放在顶栏）→ 桥接自动接上 → 选「从 Zotero 导入」或「新建空文献库」→ 引导检索教程（3 步，每步可跳过）→ 确认后加入第一篇论文 → 侧边栏出现 mdtero AI 生成的摘要。
- **放行**：Jianbin 在内部版上验收通过 → 小范围内测。
- **延后**：Vercel Web Analytics、Apple 开发者账号（签名和公证）。

### 5.1 内置模型「mdtero AI」
- 中英文界面都叫「mdtero AI」，不显示模型名。
- 后端代理到 sub2api，key 只放在服务端，每个账号每天有调用上限。客户端里永远没有 key。
- 群里贴过的 key 作废，需要 Jianbin 轮换新 key 并私发工程主管（待办）。

### 5.2 引导与 Zotero 导入 v1
- 登录/注册后只问一件事：从 Zotero 导入，还是新建文献库。然后进引导检索，把论文加进库。
- 导入 v1：拖入 `.bib`、`.ris`、Zotero JSON、CSL JSON；单个文件不超过 1 MiB 或 500 条，客户端自动分批；先预览，确认后再写入；500 条 1 分钟内导完。读取本机 Zotero 7 的接口放到后面做。
- 元数据全部导入；全文只在用户主动操作时获取。

### 5.3 全文出口（原 relay）
- 不是 VPN：只走白名单里的出版社域名，只用用户自己的设备。
- 一个账号可以有多个出口，默认「自动」，另有开关；用设备码配对。
- 获取时显示「经由：<出口名>」；某个出口失败时自动换下一个，并提示用户。
- 排期：OAuth 之后约 2 天。

### 5.4 获取全文队列（参考 Zotero 的交互）
- 入口：右键菜单、工具栏、阅读器里的按钮。已经有全文的自动跳过。
- 数量不设硬上限，超过 20 篇先确认；逐篇顺序执行，有进度条，可以暂停和取消。
- 每行状态：排队中 / 获取中 / 全文已就绪 / 仅元数据（附原因）。
- 同一出版社域名之间随机间隔 3 到 5 秒；连续失败 3 次就暂停这个域名；遇到验证码就暂停并显示黄色提示条，不绕过。
- 重启后提示是否继续；文献库可以按全文状态筛选。

### 5.5 只输出 Markdown
- 来源顺序：开放 XML（PMC/EuropePMC JATS、Elsevier XML API、Springer OA、MDPI/Frontiers）→ 经用户的 Chrome 或全文出口取出版社 HTML → 最后才解析 PDF，并标注「来源：PDF 解析（排版可能有误）」。
- 界面上不出现"PDF"字样（上面这条来源标注除外）；导出只有 `.md`。
- 验收：OA 回归集里走 PDF 兜底的比例低于 10%。

### 5.6 UI 统一
- 共享 `tokens.css` 和组件，放在 `doi2md/contracts/`；砖红 #a3542f 用在所有地方，包括后端的 MCP 页面；品牌名一律小写 mdtero。
- P0：去掉原始报错和内部术语。深色模式和中文版 `/docs` 放到闭环之后。
- 关于页显示「0.1.0 内测版」/「0.1.0 Beta」。

### P0 基线与稳定性
- **埋点**：区分来源（desktop / relay / cli / mcp）、调用方的 AI 软件和操作系统。成功分成"拿到全文"和"只拿到摘要"两档。内部流量单独打标签。
- **漏斗**（延后）：Vercel 访问 → Cloudflare 下载 → 首次登录 → MCP 接入。
- **回归集**：15 到 20 篇，每家主要出版社 1 篇，再加 5 篇只有 PDF 的，每次发版自动跑。
- **稳定性**：取全文、解析、入库三个阶段分别记心跳，卡住自动重试一次。部署时 worker 先跑完手上的任务再退出，中途被替换的任务重新排队。
- **发版规则**：发版前必须用生产配置跑测试；部署后自动验证；验证不通过就自动回滚。

### P1 MCP 第一期
- **三个任务级只读工具**：检索文献库、按 DOI 取全文、查任务结果。**按段落引用不在一期**，要等语义检索做出来。
- 取全文按"文献库、云端、本机客户端、全文出口"的顺序路由。超过 25 秒先返回"正在获取"，不能卡死。其余 27 个细粒度工具默认隐藏。
- **写入工具风险**：现在 main 上对外暴露 8 个写入工具。外部 MCP 默认隐藏写入工具，和 #81 第一次部署一起上。等 OAuth 拆分出只读和写入权限后，写入工具才重新开放，而且只能"写入待确认区"。这是 MCP 推广的前提。
- 客户端里的"接入 AI"页先支持 Codex 和 Claude Code。Cursor、Claude 桌面版和 Grok Bot 并排放成接入卡片，没验证完的显示"即将支持"。
- **统一 OAuth**：网站、客户端、全文出口、MCP 都用同一个 mdtero 账号授权，不再粘贴 token。#81 合入后约 6 个工作日，约 11/5 完成，算进 MCP 一期验收。
  - 已经有的：授权服务器信息、客户端自助注册（回调地址白名单）、授权确认页 `/mcp/connect`、撤销接口 `/revoke`。
  - 要补的（约 4 天）：权限拆成只读和写入（一期只显示只读，写入以后单独勾选）；授权页用大白话写明哪个应用在请求、能做什么，比如"读取你的文献库"，配"允许"和"拒绝"两个按钮；网站加"已授权的应用"列表，撤销后令牌立即失效；客户端改成打开系统浏览器授权，再自动回到客户端并接上桥接。
  - 要补的（约 2 天）：全文出口和无界面 CLI 用设备码登录，终端显示短码，在网站"设备"页输入，走同一个授权页。
  - 令牌不能带出用户的 BYOK 密钥，服务端调用时只用令牌对应的权限。
- **Grok Bot 接入**：以远程 MCP 连接器接入 `https://api.mdtero.com/mcp`。把 Grok Bot 的 OAuth 回调地址加进白名单，排在 OAuth 第一部分之后，从授权到取一篇 OA 论文完整跑通。跑通后作为 MCP 宣传的第二个演示。再配一个 mdtero 技能模板，写明"先查库，再取全文；AI 取到的论文进待确认区"。
- **MCP 一期验收**：约 11/5 OAuth 完成后，验收通过再推广。

### P2 待确认区和入库工具
- AI 取来的论文先进待确认区，保留 **14 天**，到期前 2 天提醒，不占配额；入库前要确认。
- 到期没确认的论文，连同原始文件一起删除。

### P3 密钥与订阅
- "服务与密钥"页：用户可以自带 MinerU、OpenAlex 等服务的 key。基础订阅里包含少量 PDF 解析额度。
- 定价出来之前，Stripe 只用测试模式。

### 研究模式 v1（AI agent）
- **目标**：在文献库、阅读器或检索结果里选几篇论文，点"用 AI 研究"，再点一个预设任务，右侧边栏就生成一份 Markdown 文档。整个过程不切换页面，也不用自己写提示词。
- **底座**：复用 #16 的 Pi agent（`@earendil-works/pi-coding-agent`，MIT 许可证，第三方声明已写），以及 #16 里已有的 `/` 选文献（最多 10 篇）、可折叠步骤卡片和 OpenAlex 检索。不重写 agent。模型用 mdtero AI。
- **六个预设任务**：比较研究方法（对比表）、总结各篇摘要、对比主要结论、提取实验参数成表、列出研究空白、写综述草稿（每句话标出处）。界面上一排放四个，另外两个收进"更多"。没选论文时提示先选文献。
- **Markdown 文档栏**：支持表格、公式和代码块，渲染前先做 HTML 清洗；可以编辑、复制、导出成 `.md`；引用点一下就跳到阅读器里那篇论文；"存入文献库"之前必须先弹确认卡片。阅读器里选中的文字也能直接发给 AI。
- **验收**：选 5 篇已经解析好的论文，点"比较研究方法"，60 秒内在侧边栏出现带引用的完整表格；每条引用都能对应到原文；没有全文的论文要标出"仅基于摘要"。
- **排期**：预设任务和侧边栏 11/3 到 11/7；设计稿 10/28 起出。
- **参考边界**：Open Notebook（lfnovo/open-notebook）是 MIT 许可证，主要借鉴思路，复用代码的话要在第三方声明里写上它的版权。

### 检索与引文网络 v1
- 检索结合 OpenAlex 的接口来做，界面要更好看。
- **引文网络**：借鉴 Connected Papers 的思路，界面和算法都自己做。输入一篇种子论文，用 OpenAlex 的参考文献和被引数据，按共同引用和共同参考算相似度，画 30 到 50 篇论文的网络图。节点大小代表被引次数，颜色代表年份。
- 点节点时侧边显示摘要，可以一键"加入待确认区"，不直接写入文献库。每篇论文都能跳到它的 DOI 页面。
- OpenAlex：先查服务端共享缓存；用户自己的 key 存在本机钥匙串，没有就用托管额度。检索和建图都不消耗 PDF 解析额度。
- **验收**：第一批节点 ≤3 秒，整张图 ≤15 秒，节点分批加入并显示"正在扩展网络"；已缓存的论文 ≤5 秒。
- **排期**：设计稿 10/28 起出；取数原型和前端开发排在 MCP 一期验收之后。

## 9. 验收标准（总）
- 最小闭环：见第 5 节，新用户 10 分钟走完。
- MCP 任务中"拿到全文"的比例 ≥ 95%（不算内部流量）；每周卡住的任务数可见，并且持续下降。
- 本机客户端在线时，订阅论文 10 次里成功 9 次以上，从调用到返回不超过 2 分钟。
- 本机客户端离线、需要登录、额度用完、key 失效时，AI 收到一句能照着做的话，不出现错误码。
- 在任务跑到一半时部署一次，任务仍然成功完成。部署后验证失败时会自动回滚。
- 新用户从装好客户端、在浏览器授权登录，到在 Claude Code 里拿到一篇论文的全文，5 分钟以内。
- 所有 MCP 接入都走 OAuth 授权页，不用粘贴 token；撤销后，对应应用的下一次调用立即失效。
- 无界面版：一条命令装好，设备码登录，取一篇订阅论文并入库，在网站上能看到这台设备在线。

## 10. 底线
- 不对接盗版来源，不绕过验证码或反爬，不在用户未确认时写入文献库，不碰用户密钥。
- Cookie、账号和凭据永远不离开本机。出版社原文只存进这个用户的私有空间，不共享，也不做跨用户缓存。
- 用户不确认，不往正式文献库里写东西。这一条对 MCP、研究模式和引文网络都适用。
- key 加密存储，不写进日志，界面上只显示后四位。令牌不能带出 BYOK 密钥，密钥也不经过第三方 AI 软件。
- **许可证**：Zotero translators（AGPL）在 `THIRD_PARTY_NOTICES.md` 里登记，公开发布前请懂许可证的人审一遍；关于页加「开源许可」。llm-for-zotero（AGPL）和 Zotero 只借鉴思路，不用代码、CSS 和图标。
