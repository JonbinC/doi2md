# mdtero PRD 草稿（2026-10-23 群内讨论后更新，待 Jianbin 确认）

## 1. 定位
mdtero 是 AI 编程和研究工具（Claude Code、Codex、Cursor、ChatGPT、Grok Bot 等）的文献层：把任何一篇论文变成干净、可追溯的 Markdown，存进用户的私有文献库，再通过 MCP 交给 AI 使用。
差异化来自三样东西：独有的解析能力、用用户自己的网络取全文的能力（本机客户端和 relay），以及私有文献库。
> 文献库实际存储位置（R2 / GCS / 服务器本地）还没查清。查清之前，对外不写"5 GiB 私有云端文献库"，只写"私有文献库"。如果确认存在服务器本地，要先迁移再宣传。

## 2. 产品线
| 对外名称 | 作用 | 状态 |
|---|---|---|
| mdtero 网站 | 账号、文献库、设备、服务与密钥、订阅、已授权的应用 | 保留 |
| mdtero 客户端（桌面版） | 取订阅全文、一键接入 AI、文献库、阅读器、研究模式 | 主力 |
| mdtero 客户端（无界面版，`mdtero` 命令） | 在 Pi、NAS、服务器上取全文，用设备码登录 | 保留，改用 Go 核心 |
| MCP | 把文献库和取全文能力接进 AI 软件 | 第一优先 |
| 浏览器扩展 | — | 冻结，加迁移横幅 |

界面上不出现 Connect、relay、Pi 这些内部名。

### 2.1 共享 Go 核心（架构决定）
- 用一份 Go 核心替换现在 PyInstaller 打包的桥接，桌面版和无界面版共用。
- CLI 只做一层薄壳，调用 Go 核心。
- Python 版 relay 和 CLI 归档，不再维护。
- 接口契约放在公开仓库 doi2md 的 `contracts/` 目录下，包括状态码对照表，客户端、服务端和 MCP 共用。

## 3. 目标用户与核心场景
目标用户：大量读英文论文、用 AI 工具写代码、做综述的理工科研究者。
1. 在 AI 软件里说"读一下这个 DOI"，就能拿到全文，订阅论文也一样。
2. 检索自己的文献库，按段落引用放到语义检索之后（P4）。
3. AI 取来的论文先进待确认区，用户确认后才存进文献库。
4. 选几篇论文，点一个预设任务，侧边栏就生成一份带出处的 Markdown 文档。

## 4. 信息架构
三个板块：**文献库**、**阅读器**、**AI agent（研究模式）**。**检索**放在最上层，任何页面都能直接用。

## 5. 路线图与排期
### P0 基线与稳定性
- **埋点**：区分来源（desktop / relay / cli / mcp）、调用方的 AI 软件和操作系统。成功分成"拿到全文"和"只拿到摘要"两档。内部流量单独打标签。
- **回归集**：15 到 20 篇，每家主要出版社 1 篇，再加 5 篇只有 PDF 的，每次发版自动跑。
- **稳定性**：取全文、解析、入库三个阶段分别记心跳，卡住自动重试一次。部署时 worker 先跑完手上的任务再退出，中途被替换的任务重新排队。
- **发版规则**：发版前必须用生产配置跑测试；部署后自动验证；验证不通过就自动回滚。
- **网站流量**：mdtero.com（Vercel 项目 `mdtero`）现在没开 Web Analytics，也没有下载按钮的点击事件，拿不到基线。开启 Web Analytics 并给下载按钮加埋点，作为推广的前置条件（需要 Jianbin 同意后再开）。

### P1 MCP 第一期
- **三个任务级只读工具**：检索文献库、按 DOI 取全文、查任务结果。**按段落引用不在一期**，要等语义检索做出来。
- 取全文按"文献库、云端、本机客户端、relay"的顺序路由。超过 25 秒先返回"正在获取"，不能卡死。其余 27 个细粒度工具默认隐藏。
- 客户端里的"接入 AI"页先支持 Codex 和 Claude Code。Cursor、Claude 桌面版和 Grok Bot 并排放成接入卡片，没验证完的显示"即将支持"。
- **统一 OAuth**：网站、客户端、relay、MCP 都用同一个 mdtero 账号授权，不再粘贴 token。#81 合入后约 6 个工作日完成，约 11/5（#81 约 10/28 合完），算进 MCP 一期验收。
  - 已经有的：授权服务器信息、客户端自助注册（回调地址白名单）、授权确认页 `/mcp/connect`、撤销接口 `/revoke`。
  - 要补的（约 4 天）：权限范围拆成只读和写入；授权页用大白话写明哪个应用在请求、能做什么，比如"读取你的文献库"，配"允许"和"拒绝"两个按钮；网站加"已授权的应用"列表，可以撤销，撤销后令牌立即失效；客户端改成打开系统浏览器授权，再自动回到客户端并接上桥接。
  - 要补的（约 2 天）：relay 和无界面 CLI 用设备码登录，终端显示短码，在网站"设备"页输入，走同一个授权页。
  - 令牌不能带出用户的 BYOK 密钥，服务端调用时只用令牌对应的权限。
- **Grok Bot 接入**：Grok Bot 以远程 MCP 连接器的方式接入 `https://api.mdtero.com/mcp`。要把 Grok Bot 的 OAuth 回调地址加进白名单，排在 OAuth 第一部分之后，从授权到取一篇 OA 论文完整跑通。跑通后作为 MCP 宣传的第二个演示。再配一个 mdtero 技能模板，写明"先查库，再取全文；AI 取到的论文进待确认区"。
- **MCP 一期验收**：约 11/5 之后。

### P2 待确认区和入库工具
- AI 取来的论文先进待确认区，保留 **14 天**，到期前 2 天提醒，不占配额；入库前要确认。
- 到期没确认的论文，连同原始文件一起删除。

### P3 密钥与订阅
- "服务与密钥"页：用户可以自带 MinerU、OpenAlex 等服务的 key。基础订阅里包含少量 PDF 解析额度。
- 定价出来之前，Stripe 只用测试模式。

### 研究模式 v1（AI agent）
- **目标**：在文献库、阅读器或检索结果里选几篇论文，点"用 AI 研究"，再点一个预设任务，右侧边栏就生成一份 Markdown 文档。整个过程不切换页面，也不用自己写提示词。
- **底座**：复用 #16 的 Pi agent（`@earendil-works/pi-coding-agent`，MIT 许可证，第三方声明已写），以及 #16 里已有的 `/` 选文献（最多 10 篇）、可折叠步骤卡片和 OpenAlex 检索。不重写 agent。
- **六个预设任务**：比较研究方法（对比表）、总结各篇摘要、对比主要结论、提取实验参数成表、列出研究空白、写综述草稿（每句话标出处）。界面上一排放四个，另外两个收进"更多"。没选论文时提示先选文献。
- **Markdown 文档栏**：支持表格、公式和代码块，渲染前先做 HTML 清洗；可以编辑、复制、导出成 `.md`；引用点一下就跳到阅读器里那篇论文；"存入文献库"之前必须先弹确认卡片。阅读器里选中的文字也能直接发给 AI。
- **验收**：选 5 篇已经解析好的论文，点"比较研究方法"，60 秒内在侧边栏出现带引用的完整表格；每条引用都能对应到原文；没有全文的论文要标出"仅基于摘要"。
- **排期**：#16 合入后 5 个工作日。#16 的合入日期还没定，需要尽快定。设计稿 10/28 起出。
- **参考边界**：Open Notebook（lfnovo/open-notebook）是 MIT 许可证，主要借鉴思路，复用代码的话要在第三方声明里写上它的版权。llm-for-zotero 是 AGPL，只能借鉴思路，不用它的代码、CSS 和图标。

### 检索与引文网络 v1
- 检索结合 OpenAlex 的接口来做，界面要更好看。
- **引文网络**：可以借鉴 Connected Papers 的思路，但界面和算法都自己做。用户输入一篇种子论文，用 OpenAlex 的参考文献和被引数据，按共同引用和共同参考算相似度，画 30 到 50 篇论文的网络图。节点大小代表被引次数，颜色代表年份。
- 点节点时侧边显示摘要，可以一键"加入待确认区"，不直接写入文献库。每篇论文都能跳到它的 DOI 页面。
- OpenAlex 调用优先用用户自己的 key，没有 key 就用托管的额度。检索和建图都不消耗 PDF 解析额度。
- **验收**：首次建图 3 秒内出现第一批节点，15 秒内建完整张图，节点分批加入并显示"正在扩展网络"；同一篇论文第二次建图 5 秒内出来（靠服务端缓存）。
- **排期**：设计稿 10/28 起出；取数原型和前端开发排在 MCP 一期验收之后。

## 7. 成本与基础设施
- R2 的成本可以忽略，真正的成本是 MinerU、Voyage 和 LLM 的调用。
- `trove-downloads` 属于另一个项目，不算进 mdtero 的成本，我们也不去动它。
- **安装包分开放**：新建 `mdtero-downloads` 桶，挂到 `download.mdtero.com/client/`，网站下载按钮改指新地址。
  - 文件名只用英文：`mdtero-client-<版本号>-mac-arm64.dmg` 和 `mdtero-client-<版本号>-win-x64.exe`，各留一个 latest 别名。界面上显示的名字照样叫"mdtero 客户端"。
  - Jianbin 在 Mac 和 Windows 上都从新链接装成功之后，再看清单决定是否清理 `trove-downloads/connect/` 下的 mdtero 文件。其他文件都不动。

## 8. 验收标准（总）
- MCP 任务中"拿到全文"的比例 ≥ 95%（不算内部流量）；每周卡住的任务数可见，并且持续下降。
- 本机客户端在线时，订阅论文 10 次里成功 9 次以上，从调用到返回不超过 2 分钟。
- 本机客户端离线、需要登录、额度用完、key 失效时，AI 收到一句能照着做的话，不出现错误码。
- 在任务跑到一半时部署一次，任务仍然成功完成。部署后验证失败时会自动回滚。
- 新用户从装好客户端、在浏览器授权登录，到在 Claude Code 里拿到一篇论文的全文，5 分钟以内。
- 所有 MCP 接入都走 OAuth 授权页，不用粘贴 token；撤销后，对应应用的下一次调用立即失效。
- 无界面版：一条命令装好，设备码登录，取一篇订阅论文并入库，在网站上能看到这台设备在线。

## 9. 底线
- Cookie、账号和凭据永远不离开本机。出版社原文只存进这个用户的私有空间，不共享，也不做跨用户缓存。
- 用户不确认，不往正式文献库里写东西。这一条对 MCP、研究模式和引文网络都适用。
- key 加密存储，不写进日志，界面上只显示后四位。令牌不能带出 BYOK 密钥，密钥也不经过第三方 AI 软件。
- 不对接盗版来源，不绕过验证码或反爬。
- AGPL 项目只借鉴思路，不用代码。
